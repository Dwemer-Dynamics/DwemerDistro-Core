# Optional LM Studio component

Run `sudo /usr/local/bin/install_lmstudio` after updating DwemerDistro. This installs the reviewed upstream headless engine for `dwemer`. It does not download a selected language model, load one, enable autostart, or change game providers. The upstream bootstrap script is checksum pinned; refresh it only after reviewing a new upstream version.

The launcher opens `/Dwemer-Dashboard/lmstudio.php` with a private access key in the URL fragment. The page exchanges it for an eight-hour session and removes the fragment. You can also run `ddistro_lmstudio access` as `dwemer` and paste the key. Do not share the key. Management requests require the session and a CSRF token; `www-data` may invoke only the restricted helper as `dwemer`.

The OpenAI-compatible base URL inside WSL is `http://127.0.0.1:1234/v1`; the full chat URL is `http://127.0.0.1:1234/v1/chat/completions`. Port 1234 is reserved for this component. Stop another server using that port before starting LM Studio. The manager remains usable while inference is stopped. It polls only while visible and never generates on page load.

Presets live in `/etc/dwemerdistro-lmstudio.json`, shared by Quickstart and the web manager. They pin a Hugging Face repository, revision, file, size and SHA-256. Downloads resume after interruption, verify the whole file, and import through `lms`. Custom inputs accept Hugging Face URLs (for example `https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF@Q4_K_M`) or LM Studio catalog IDs; those use upstream selection and verification. No model is labelled recommended without separate game-quality testing.

**Import local model** registers a standalone `.gguf` file that is already on the Windows PC hosting DwemerDistro. Paste its full path (`C:\Models\model.gguf`, or `/mnt/c/Models/model.gguf`); nothing is uploaded from the browser and there is no file browser. The source must be a regular file on a mounted Windows drive (`/mnt/<letter>`), reached without links, shortcuts or junctions anywhere in the path. The helper checks the GGUF header and metadata (version 2 or 3) rather than trusting the extension, and refuses other formats, malformed files and split sets (`-00001-of-0000N` or `split.count` metadata). Metadata parsing is bounded (key length, total metadata size, entry count and time), so a crafted file cannot exhaust memory or hold the worker; real large-vocabulary metadata is well inside these limits. A `split.count` of type UINT16 above 1 marks a shard; a merged model's `split.count` of 0 is accepted, and any other type is refused as malformed. It reads the original without changing it, copies it in bounded chunks with progress into private staging under the manager state folder, and refuses a source that changes during the copy. The model is registered with `lms import --user-repo local/<file name> --yes --hard-link` into the folder `lms` itself uses (`~/.lmstudio-home-pointer`, then `settings.json` `downloadsFolder`), so it occupies one copy of the file. If that folder is on another filesystem, `--copy` is used and the import needs space for two copies, one on each side. Each location needs the file size plus 1 GB free. An existing `local/<file name>` model is never overwritten; rename the file to import another copy. Staging is cleared after each import and after an interrupted one. Before registering, the helper records the staged file identity and destination. If registration fails or is interrupted, it removes the destination only when it is still the same staged file (a hard link). It never uses timestamps or file size alone to infer ownership. A cross-filesystem registration copy, or a replacement file created by another program, is preserved and its path is reported for manual inspection before retrying. An incomplete copy may therefore remain in a custom model folder after failure; inspect it, or rename the source to import under another name. A file that `lms` reports as already present is always preserved. Ollama stores models as managed blobs, not ordinary GGUF files, so they are not imported here; connect CHIM to Ollama instead. Importing does not load the model or change game providers.

Manager state and temporary downloads are under `/home/dwemer/.config/dwemerdistro/lmstudio` (private to `dwemer`). LM Studio manages its own model directory, normally `/home/dwemer/.lmstudio/models`. Updates and reinstall preserve these locations. Turning off autostart or stopping the engine leaves downloads in place. There is deliberately no destructive remove-model or delete-runtime action.

One manager job runs at a time. Load accepts context length, GPU offload percentage and idle TTL. It checks free RAM/VRAM with 2 GB headroom; upstream guardrails still apply and context increases memory needs. Unload before switching.

Advanced loading uses the official Python SDK, pinned to `lmstudio==1.5.0` in the root-owned `/opt/dwemerdistro-lmstudio` virtual environment. Run the component installer again after upgrading an earlier installation to add this dependency. Basic loading remains available without it. Controls include Flash Attention, GPU KV-cache offload, a strict GPU memory cap, keep-in-RAM, mmap, evaluation batch size, seed, K/V cache precision, and RoPE frequency base/scale. Empty fields retain engine defaults. Quantized V cache requires explicitly enabled Flash Attention. The manager displays the engine-reported load configuration; support still depends on the model and runtime.

Save loading defaults separately for each model. They apply in this manager and when DwemerDistro starts an optional selected startup model; they do not rewrite the upstream desktop app's configuration. Autostart remains opt-in. Disabling it preserves defaults and downloaded models. Startup uses the same validation, memory checks, and job lock as manual loading; a failed startup load is visible in Current operation.

Test requests require an already loaded model. Temperature, top-P, top-K, min-P, repeat penalty, system prompt, thinking and output limit apply only to the test console, never game connectors. The default output limit is 192 tokens; the maximum is 4,096. Unsupported thinking settings return an error. The last successful bounded response, token counts, speed, time to first token and settings remain available across page reloads. A truncated stream is treated as failure. Saved test presets support browser JSON import/export using the versioned `dwemer-llm-test-v1` format, not the desktop app's preset format. State stays private to `dwemer`; at most 50 model defaults and 10 test presets are stored.

The manager is not a replacement for every desktop feature. CPU-thread overrides, stop strings, parallel-request tuning, speculative decoding, custom prompt templates, runtime switching, LAN/authentication/CORS and JIT-server policy controls are not exposed. The fixed loopback endpoint preserves the shared Quickstart connector contract. Full chat history, documents/RAG and MCP tooling are outside this component's game-serving purpose.

The integration was developed against llmster `0.0.25-1` / lms commit `69d945a`. Core, Dashboard and Launcher changes must ship together. Local model import needs this Core helper and the matching Dashboard manager; an older helper rejects the import action as unknown. Existing onboarding completion stays valid. In-game provider quality and large-model fit must be measured separately from successful component installation.
